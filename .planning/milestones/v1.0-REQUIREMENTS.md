# Requirements - 3F v1.0

## 🎯 Goal
Stabilize the existing brownfield codebase into a production-ready v1.0 version for personal financial management.

## 🏗️ Core Functional Requirements
- [x] **Ledger Reliability**: Finalize and audit the `LedgerEngine` to ensure accurate balance calculations across all account types (ASSET, LIABILITY, etc.).
- [x] **Transaction Management**: 
  - [x] Complete CRUD for transactions.
  - [x] Support for multi-category and multi-account splits (Double-Entry).
  - [x] Bulk transaction import (CSV/Excel).
- [x] **Organization**:
  - [x] Hierarchical category management.
  - [x] Payee/Beneficiary database with default category mapping.
- [x] **Reporting**:
  - [x] Integrated Cashflow analysis.
  - [x] Expense Heatmaps.
  - [x] Account forecast (Financial projection).
- [x] **Automation**:
  - [x] Functional plugin system.
  - [x] **PaddleOCR Integration**: Automatic receipt parsing into transaction drafts. -> Modificado: Descartado a favor del motor hardcoded determinista.
- [x] **Security**:
  - [x] Local authentication (JWT).
  - [x] Encrypted environment variables.

## 🎨 UI/UX Requirements
- [x] **Neon Dashboard**: A fully responsive landing page with key stats (Total Net Worth, Monthly Burn Rate).
- [x] **Dynamic Sidebar**: Reactive account list with real-time balances.
- [x] **Micro-interactions**: Use Alpine.js for smooth state transitions without full page reloads.

## 🛠️ Technical Requirements
- [x] **Database**: SQLModel with Alembic migrations for schema evolution.
- [x] **Testing**: Playwright coverage for critical paths (Login -> Add Transaction -> Verify Balance).
- [x] **Performance**: Optimize SQL queries for calculating balances in sub-200ms.
